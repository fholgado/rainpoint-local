# HCS02x soil-moisture sensor protocol

This definition covers the shared HCS02x RF capability and has been physically
validated with `HCS026FRF` sensors. Ordinary telemetry does not expose enough
information to distinguish every retail model in the family.

## Identity

| Property | Definition |
|---|---|
| Factory endpoint suffix | `24` |
| Paired endpoint | Factory endpoint with `0x80` set in its first byte |
| Factory broadcast peer | `80 00 00 00` |
| Shared RF product code | `0x48` for the HCS021/HCS024/HCS026 capability family |
| Exact model code | `0x013d` when present in product metadata |
| Supported local profile | `hcs026_auto_v1` |

Two validated transformations are `1b ce 00 24` to `9b ce 00 24` and
`15 a9 80 24` to `95 a9 80 24`. These values are evidence examples, not fixed
installation defaults.

A strict factory announcement has message signature:

```text
01 00 83 82 7f a4 1e 80
```

The gateway derives the device identity from this announcement. It must not
hard-code a household sensor ID or infer a model name from moisture telemetry.

## New enrollment

The selected custom radio node listens for the strict factory announcement,
derives the paired endpoint, and assigns a generated custom-gateway
controller/companion identity. The validated automatic profile assigns
selector `4` and uses the common selector-to-frequency mapping.

The exchange has three gateway replies:

| Trigger from sensor | Gateway action |
|---|---|
| Factory message 1 | Send assignment reply 1 to the new paired endpoint |
| Paired message 1 | Send reply 2 |
| Paired data message 2 | Send reply 3 |
| Short message 2 | Observe only |
| Terminal paired message 3 | Mark enrollment complete; do not reply |

All enrollment replies use the 320-symbol wake-up form. Exact reply bodies,
field masks, integrity residues, and bounded timing are generated by
`pairing_protocol.py` and frozen by its fixture tests.

Reply 1 contains a packed local wall-clock and date:

- time in bytes `21..22`, FAT/DOS-style;
- date in bytes `23..24`, with the year based at 2020;
- the current validated profile uses the configured pairing clock lead.

The stock RainPoint gateway must be powered off during new local enrollment.
Two gateways answering the same factory exchange collide and make completion
nondeterministic.

## Retained-association recovery

A known paired sensor can re-announce with its factory endpoint after a power
cycle or dormant period. The custom gateway recognizes the strict factory
signature, preserves the existing paired endpoint and ACK owner, and performs
a bounded rejoin rather than creating a new Home Assistant device.

An already authorized sensor may also replay the paired recovery sequence:

```text
paired message 01 -> paired data 02 -> paired short 02 -> paired terminal 03
```

The gateway answers this sequence only for a previously authorized endpoint.
Validated recovery counters include `1`, `2`, and `4`; they are not assumed to
restart at one.

## Routine moisture report

The moisture marker is the low seven bits `0x44`, found at normalized offset
`18` or `20` depending on the report form. The following byte contains the
even part of the percentage, and the high bit of the next byte is the odd bit:

```text
moisture_percent = value * 2 + bool(odd_flag & 0x80)
```

The physical display range is `1..99`. The decoder tolerates the boundary
values `0` and `100` but rejects values outside `0..100`.

An alternate product/TLV report may use endpoint suffix `48` and a direct
`88 VV` moisture value. When its surrounding identity fields match a known
sensor, it is canonicalized to that sensor's suffix-`24` endpoint rather than
creating a second device.

The HCS026 manual distinguishes measurement from reporting: it measures every
three minutes and refreshes the gateway/app about every eight minutes, after a
manual detection, or when an automatic reading changes by more than five
percentage points. Stable moisture therefore reduces event frequency but does
not suppress all routine reports.

## Battery state

In a routine moisture report, inspect the byte immediately before the moisture
marker:

```text
bit 0x04 set    normal/full category -> expose 100%
bit 0x04 clear  low category         -> expose 10%
```

This is categorical, not a measured percentage. If the marker or status bit is
absent, battery is unavailable.

## Routine report acknowledgement

Every accepted paired moisture report receives one acknowledgement from its
assigned ACK owner. If the report routes `controller -> sensor`, the ACK routes
`sensor -> companion`, where the companion is the controller endpoint with its
first-byte high bit cleared.

The acknowledgement body is derived from the report:

```text
body[0] = report body[0] | 0x80
body[1] = report body[1] | 0x40
body[2..4] = 81 00 01
body[5..22] = 00
```

It preserves the association's integrity residue. The validated reply begins
approximately 177--188 ms after the report sync and transmits on the sensor's
negotiated selector channel. Multiple receiving nodes may forward the report,
but only the persistent owner transmits the ACK.

Without accepted ACKs the sensor can eventually stop routine reporting. A
manual press or retained-association recovery may revive it, but the durable
fix is correct ACK ownership and delivery.

## Fields not present in routine RF telemetry

- Exact retail model name, unless separate product metadata is available.
- App Device Address; it is not the byte previously suspected at offset `15`.
- RSSI; this is measured by the receiver.
- Soil type (`P1` mixed, `P2` peat, `P3` black earth, `P4` sandy loam,
  `P5` laterite, `P6` other).
- Cloud-configured alerts and associated-controller settings.

An associated-controller moisture relay uses an HTV145-style route and does
not carry the sensor endpoint. It remains an unassigned event unless separate
metadata proves the source.
